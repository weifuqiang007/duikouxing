# 1.业务梳理
2个业务场景的共同点：人基本不动，人手持身份证或者其他证件，机械的念完一段话即可。

场景1 客户提供一段视频A和一个人物头像三视图B。希望将视频A中的人物头像换成B的。说话声音保持视频原声。但是要人物形象好一点，不要有明显人物换头的不贴合感。人说话，嘴唇要动。二者有关联关系。不能人说话，但是嘴唇乱动。

场景2 客户提供一段视频A、另外一段口播话术C。且已知C的语音长度比A长。现在希望使用技术，让A能说出C话术。要求就是说话的时候要像本人在读，口型要好，不要有明显的贴缝，最好是像克隆出来的数字人一样，正常、自然地读完这段话。

### 回答
我读了项目文档。这个项目现在其实有两条线：

1. **业务线 1：对口型配音**
   - 输入：原视频 + 新音频/新话术
   - 核心：让嘴型跟新声音对上
   - 主线是 **LatentSync 1.6**，MuseTalk 是本地回退/对照

2. **业务线 2：换头**
   - 输入：客户身份证照片 + 工作人员录制的视频
   - 核心：把视频里工作人员的“头”换成照片里的人
   - 这里才用到 **LivePortrait**

## LivePortrait 是干嘛的？

在这个项目里，**LivePortrait 不是口型同步模型，也不是普通换脸模型**。

它的作用是：

> **把一张静态肖像照片“驱动起来”，让照片里的人跟随一段视频做头部动作、表情和口型。**

具体到你的项目，就是：

```text
身份证照片/标准肖像
        +
工作人员宣读视频
        ↓
LivePortrait
        ↓
照片人物被驱动起来的视频头部
```

也就是说：

- **脸是谁的？**  
  来自照片，比如 `11.png`

- **头型、发型、耳朵是谁的？**  
  理想情况下也来自照片

- **动作、点头、表情、嘴巴开合节奏是谁的？**  
  来自工作人员视频，比如 `wlh.mp4`

- **声音是谁的？**  
  业务线 2 里一般直接用工作人员视频原音频，因为本来就是工作人员在念最终内容

## 它和 FaceFusion 的区别

FaceFusion 更像是：

> 把一张脸贴到视频里原人物的内脸区域。

所以它通常只能换：

- 眼睛
- 鼻子
- 嘴
- 脸中间区域

但它换不了：

- 发型
- 整体头型
- 耳朵
- 后脑勺
- 头发轮廓

项目文档里也明确说了：FaceFusion 的 inswapper_128 本质只生成 128×128 的内脸区域，**没有能力生成头发像素**。

LivePortrait 的价值就在于，它不是只换内脸，而是让“照片里的整颗头”动起来，所以更适合“换头”诉求。

## 它和 LatentSync / MuseTalk 的区别

LatentSync / MuseTalk 解决的是：

> 视频已经是这个人了，只是嘴型要跟新音频对上。

LivePortrait 解决的是：

> 视频里不是这个人，要让照片里的人变成会动、会说话的头。

所以：

| 模型 | 主要用途 | 本项目里属于 |
|---|---|---|
| LatentSync | 高质量口型同步 | 业务线 1 主线 |
| MuseTalk | 本地口型同步回退 | 业务线 1 回退 |
| FaceFusion | 换内脸 | 业务线 2 现状基线 |
| DreamID-V | 生成式视频换脸 | 业务线 2 实验对照 |
| **LivePortrait** | **肖像再演 / 整头驱动** | **业务线 2 方案 A 核心** |

## 一句话总结

**LivePortrait 在这个项目里是“换头方案 A”的中间核心：先把客户照片做成标准肖像，再用 LivePortrait 让这颗头跟随工作人员视频动起来，最后把这个新头贴回原视频。**

它不是最终成片工具，后面还需要“回贴合成”：分割原头、补背景、对齐新头、处理脖子接缝和肤色。

# 场景 1：换头像，但保留视频原声

你的需求本质是：

> 视频里的人说原来的话，声音不变；但头部形象要变成 B，而且嘴巴要跟原声一致。

这个不是“对口型配音”，而是**整头替换 / 头像再演**。

## 推荐路线

```text
头像三视图 B
   ↓
选正脸/半侧最佳图 + 肖像归一化
   ↓
LivePortrait 再演
   输入：B 的头像
   驱动：视频 A
   输出：B 这个人的头，跟着 A 的头动、嘴动、表情动
   ↓
整头回贴合成
   抠掉 A 的原头
   补背景
   新头对齐贴回
   脖子/发际线/肤色羽化
   ↓
最终视频：声音仍然是 A 原声
```

## 为什么 LivePortrait 适合场景 1？

因为 LivePortrait 做的是：

> **用一张人物肖像作为外观，用另一段视频作为动作驱动，让照片人物动起来。**

这正好对应你的场景：

- 身份 / 形象：来自 B
- 头部动作：来自 A
- 嘴巴开合节奏：来自 A
- 声音：保留 A 原声
- 身体 / 手 / 证件 / 背景：保留 A

LivePortrait 官方论文和项目定位也是“portrait animation”，即用 source image 和 driving motion 生成会动的肖像。它强调 stitching 和 retargeting control，适合做这种肖像再演任务。参考：[LivePortrait arXiv](https://arxiv.org/abs/2407.03168)、[LivePortrait GitHub](https://github.com/KwaiVGI/LivePortrait)。

## 为什么不建议只用 FaceFusion？

FaceFusion 可以作为低成本基线，但它最大问题是：

> 它主要换“内脸”，不是换“整颗头”。

所以它很难解决：

- 发型不像
- 头型不像
- 耳朵不像
- 脸和原头边界有贴片感
- 胖瘦脸型还是 A 的

你的场景 1 明确要求“人物形象好一点，不要明显换头不贴合”，所以 FaceFusion 单独做不够。

## 场景 1 的最佳工程方案

我建议你把它定为：

> **LivePortrait 负责“让 B 的头动起来”；分割合成负责“自然贴回 A 视频”。**

重点不是 LivePortrait 单独出片，而是后面的合成：

1. 对 A 做头部分割，包含头发区域；
2. 用背景底板补掉原头；
3. 用关键点把 LivePortrait 输出的新头对齐回原视频；
4. 脖子、发际线、脸颊边缘做羽化；
5. 做 LAB 肤色匹配；
6. 最终音轨直接 copy A 原声。

# 场景 2：视频 A 说新话术 C，且 C 比 A 长

这个需求本质是：

> 让 A 这个人像本人一样自然读完更长的新话术 C。

这不是换头，而是**声音克隆 + 口型重写 + 视频延长**。

## 推荐路线

```text
视频 A
   ↓
提取参考声音
   ↓
声音克隆 TTS 生成话术 C
   ↓
因为 C 比 A 长，所以延长 A 的无声视频
   乒乓循环 / 片段循环 / 静态身体底板
   ↓
LatentSync 1.6 做口型同步
   输入：延长后的视频 A + 克隆音频 C
   输出：嘴型跟 C 对齐的视频
   ↓
动态纹理回填 / 合成
   保留原片皮肤质感
   减少嘴部贴缝
   ↓
最终视频
```

## 为什么场景 2 推荐 LatentSync？

因为场景 2 的核心不是换脸，而是：

> **嘴型必须严格跟新音频 C 对上。**

LatentSync 的定位就是 audio-conditioned lip sync，用音频驱动画面嘴部生成。它比 LivePortrait 更适合“新话术配音后嘴型同步”。参考：[LatentSync arXiv](https://arxiv.org/abs/2412.09262)。

你当前项目文档里已经把 `LatentSync 1.6 cloud` 作为高画质主线，这是对的。

## MuseTalk 在场景 2 里的定位

MuseTalk 也能做口型同步，而且速度快，官方定位是 real-time high quality audio-driven lip-sync。参考：[MuseTalk GitHub](https://github.com/TMElyralab/MuseTalk)。

但按你的质量要求：

> “像克隆出来的数字人一样，正常、自然地读完”

我建议：

- **主线：LatentSync 1.6**
- **快速预览 / 批量粗筛：MuseTalk 1.5**
- **老旧备选：Wav2Lip / Wav2Lip-HD**

Wav2Lip 口型准，但画质和贴片感通常不如新方案，适合作保底，不适合作高画质主线。参考：[Wav2Lip arXiv](https://arxiv.org/abs/2008.10010)。

# 场景 2 还有一个关键问题：C 比 A 长

这是你场景 2 的最大工程点。

如果 C 比 A 长，不能简单让视频播放完停住。推荐做法：

## A. 人基本不动时，优先用“乒乓循环”

```text
A 正放 → A 倒放 → A 正放 → A 倒放
```

优点：

- 身体不会突然跳变；
- 手持证件比较稳定；
- 适合机械念稿场景。

缺点：

- 如果 A 里有明显眨眼、点头、手抖，循环点可能被看出来。

## B. 更好的做法：找“稳定片段”循环

从 A 中挑一段：

- 正脸；
- 手不动；
- 眼睛自然；
- 头部微动；
- 没有大幅表情变化。

然后用这段循环到 C 的长度，再交给 LatentSync 重写嘴部。

## C. 如果要更像数字人

可以做成：

```text
身体/背景基本用 A 的稳定底板
头部微动作保留
嘴部由 LatentSync 生成
眼睛眨动可从原视频周期复用
```

这样比全片反复循环更稳。

# 声音克隆模型建议

你现在用 dots.tts 是可以的。但如果要横向选型，我建议按这个顺序评估：

| 模型 | 适合度 | 说明 |
|---|---:|---|
| **IndexTTS2** | 高 | 有情绪和时长控制，对视频配音很有价值，尤其 C 需要控制长度时 |
| **CosyVoice2 / CosyVoice3** | 高 | 中文、多方言、零样本克隆能力强，工程生态好 |
| **F5-TTS** | 中高 | 自然度好，但部分权重/数据许可要注意商用限制 |
| **dots.tts-soar** | 中高 | 你项目已有，继续用没问题 |
| RVC / Seed-VC 类 voice conversion | 视情况 | 如果你能让真人先读 C，再做音色转换，会更稳 |

参考来源：[IndexTTS GitHub](https://github.com/index-tts/index-tts)、[CosyVoice GitHub](https://github.com/QwenAudio/CosyVoice)、[F5-TTS GitHub](https://github.com/SWivid/F5-TTS)。

如果你的目标是商业交付，我建议重点看：

1. 授权许可；
2. 中文数字、人名、公司名稳定性；
3. 语速可控性；
4. 长文本是否漂移；
5. 是否能按目标时长生成。

# 两个场景不要混用

这是最重要的判断。

## 场景 1 不要主用 LatentSync

因为场景 1 的音频本来就和视频 A 对齐。你要换的是“这个人是谁”，不是“嘴型跟新音频对齐”。

所以场景 1 应该是：

> LivePortrait / 整头再演 / 回贴合成

不是：

> LatentSync / MuseTalk

## 场景 2 不要主用 LivePortrait

因为场景 2 的人就是 A 本人，你不需要换头。你需要的是让 A 读新话术。

所以场景 2 应该是：

> 声音克隆 + LatentSync

不是：

> LivePortrait 换头

# 我的最终推荐

## 场景 1：主推

```text
B 三视图
→ 肖像归一化，选最接近 A 角度的一张
→ LivePortrait 512 / AdvancedLivePortrait
→ 头部分割 + 背景补洞 + 整头回贴
→ 原音频 copy
```

可保留 FaceFusion 作为对照，但不要作为最终主线。

## 场景 2：主推

```text
A 提取参考音频
→ IndexTTS2 / CosyVoice2 / dots.tts 生成 C
→ A 视频延长到 C 的长度
→ LatentSync 1.6 口型同步
→ 高频纹理回填 / 动态合成
→ 最终封装
```

MuseTalk 用于快速预览，LatentSync 用于正式高画质交付。

## 如果只能投入一条工程主线

优先把场景 2 做成稳定产品，因为它更标准化：

- 输入固定；
- 不涉及身份换头；
- 失败点更少；
- LatentSync 主线已经和你现有项目匹配。

场景 1 是更复杂的“换头业务线”，可以继续做实验闸门：先证明 LivePortrait 再演 + 回贴合成能过客户肉眼验收，再工程化。
