# MVP 验收标准

> 本文档仅适用于 MuseTalk 本地回退链路。LatentSync 1.6 云端主线使用
> [LATENTSYNC_CLOUD_ACCEPTANCE.md](LatentSync 1.6 云端高画质验收标准 )。

## 1. 测试素材

至少准备三组已授权素材，每组 10～30 秒：

1. 白底、正脸、普通话、不持物。
2. 白底、轻微地方口音、手持虚构证书。
3. 略有杂物背景、手持完全虚构的测试身份证。

真实身份证不得用于开发阶段验收。

## 2. 功能验收

| 编号 | 标准 | 通过条件 |
|---|---|---|
| F-01 | 本地处理 | 断开公网后，已下载模型的完整任务仍可运行 |
| F-02 | 授权门禁 | `consent_confirmed=false` 时任务必须失败 |
| F-03 | 声音克隆 | 输入参考声音与新话术后生成可播放 WAV |
| F-04 | 口型生成 | 输出视频嘴部随目标声音变化 |
| F-05 | 画面保护 | 背景、身体、手持物无生成形变；下半脸动作来源一致 |
| F-06 | 时长一致 | 最终视频与目标音频时长差不超过 1 帧 |
| F-07 | 格式 | 输出 H.264/AAC MP4，常见播放器可播放 |
| F-08 | 可审计 | `manifest.json` 包含输入哈希、模型、配置和阶段状态 |
| F-09 | 可重跑 | 中间文件存在时可跳过已完成阶段或使用 `--force` 重跑 |
| F-10 | 纹理恢复 | 痘坑/毛孔/胡茬比 MuseTalk 原始结果清晰，嘴唇和牙齿不出现旧帧重影 |
| F-11 | 无损中间件 | 合成阶段输出 FFV1 MKV，最终封装时才编码 H.264 |

## 3. 声音验收

- 由至少 3 名人员盲听原声与生成声。
- “像本人”平均分不低于 4/5。
- 新话术文字准确率不低于 99%；姓名、金额、日期、号码必须 100% 人工核对。
- 不允许出现变性、明显年龄变化、无关说话人或参考音频尾句泄漏。
- 地方口音如为合同要求，必须单独列为样本级验收，不以普通话基准替代。

## 4. 口型验收

- 正常速度观看无持续闭嘴说话、张嘴无声或明显提前/滞后。
- 逐帧抽查爆破音、双唇音和大开口元音。
- 主观音画偏移目标控制在约 ±80ms 内。
- 不出现连续 3 帧以上的明显嘴部闪烁、黑块或牙齿突变。
- 不出现固定椭圆/矩形贴片，嘴唇、脸颊、下颌和脖子的运动必须连续。
- 以 0.25× 速度检查嘴角和下颌边界，不得有随帧呼吸、拉丝或旧嘴型重影。

## 5. 画面保护验收

- 对最终无音轨视频与 MuseTalk 结果做差比较：变化应主要是下半脸高频纹理，不得出现新的低频几何形变。
- 背景、身体、衣服和手持物在 MuseTalk 阶段之后不得被纹理合成器改动（忽略编码误差）。
- 广告牌、证书、身份证区域不得被人脸纹理蒙版覆盖。
- 证件区域四角、文字、照片、二维码不得改变位置或内容。
- 手指、衣服、背景不得出现生成式重绘。

## 6. 性能与稳定性

- 4070 12GB 上连续完成 10 个 10 秒任务，无 OOM、无崩溃。
- 3060 12GB 至少完成 3 个 10 秒任务。
- OOM 时降低 MuseTalk batch size 后能够恢复。
- 单任务失败不得损坏其他任务目录。

## 7. 安全与合规

- 所有测试人物提供明确授权。
- 输出画面具有“AI生成/合成”显式标识（产品化阶段强制）。
- 日志不记录完整身份证号码。
- 提供本地任务彻底删除流程。
- 禁止将成片用于身份核验、金融开户、贷款、签约或冒充本人。

## 8. MVP 通过判定

F-01～F-11 全部通过，三组素材中至少两组通过声音、口型、纹理和画面保护验收，且失败组有明确、可复现的素材原因，才可进入界面和批量任务开发。
