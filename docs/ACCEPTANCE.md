# 功能与验收标准

## 功能验收

1. 输入客户视频、参考文字、替换话术和真人驱动视频，可输出带客户音色新话术的MP4。
2. `prepare-driving` 在没有 `driving_video` 时可独立生成导读和录制文本。
3. `run` 在缺少驱动、时长超阈值、权重缺失或外部程序失败时返回非0。
4. 最终音轨必须是 `target_normalized.wav`，不能是客户旧音轨或iPhone录音。
5. 输出时长与目标音频差不超过一帧或编码容器合理误差。
6. manifest记录输入/输出哈希、后端、固定提交、参数和状态。

## 画面硬性验收

连续10秒以上片段在1倍速和0.25倍速检查：

- 背景、身体、手、广告牌/证书/身份证内容和位置不被重绘。
- 客户头部总体姿态沿用源视频，不跟随操作者转头。
- 身份稳定，无明显变成操作者脸型、眼睛或眉毛。
- 不出现固定椭圆贴片、矩形边界、持续磨皮块或明显颜色断层。
- 嘴唇、脸颊、下颌连续；下颌线不被整片模糊抹除。
- 不出现连续2帧以上人脸丢失、黑块、嘴部冻结或剧烈跳动。
- 牙齿和口腔无持续熔化、重复牙齿或漂浮边缘。

## 口型验收

- 爆破音、闭口音和大开口元音关键位置与声音主观一致。
- 可察觉的持续提前/滞后不超过约80ms；瞬时误差不能形成连续错位。
- 句首、停顿、句尾在声音停止时回到合理闭口或自然静止。
- LSE-D/LSE-C可作版本对比，但客户盲评和逐帧检查是放行依据。

## A/B放行门槛

至少比较 `exp@0.75`、`exp@0.85`、`exp@1.0`、`lip@0.85`。3名盲评者对“口型自然度、身份保持、纹理连续、整体可信度”各打1～5分。候选版本必须每项中位数不低于4、无硬性失败，并且相对当前LatentSync/MuseTalk基线，在“嘴部模糊/贴片感”上至少2/3评审明确偏好。

## 性能验收

- RTX 3060 12GB和RTX 4070 12GB以FP16完成10秒、源最大边1280的视频，不发生CUDA OOM。
- 32GB内存下10秒样片不触发系统内存不足。
- 本阶段不规定实时速度；真实耗时、峰值显存写入报告后再制定生产SLA。

## 不通过后的定位顺序

1. 先查是否真正跟随导读，而不是只看总时长。
2. 查驱动首帧是否正脸闭嘴、客户脸是否稳定检测。
3. 比较 `exp/lip`，调整倍率0.75～1.0。
4. 查paste-back边缘和源压缩，不先叠加新ROI。
5. 动作正确但口腔纹理仍失败时，再与LatentSync高质量后端做A/B。
