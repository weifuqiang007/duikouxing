## 一、业务背景：两条业务线要分开

本项目当前有**两条独立业务线**，诉求不同、管线不同，不要混用：

| | 业务线 1：对口型配音 | 业务线 2：换头（本文档） |
|---|---|---|
| 输入 | 模板视频 + 客户音频（内容对不上） | **客户身份证照片** + **工作人员录制的视频**（说的就是最终内容） |
| 核心问题 | 嘴型要跟客户音频对上 | 视频里的人要变成照片里的人（脸+脸型+发型） |
| 语音 | 与视频原语音不一致，**需要重写口型** | 工作人员自己说，语音本来就对口，**无需口型重写** |
| 管线 | FaceFusion → LatentSync c6 | FaceFusion（现状）→ 待升级为"换头"方案 |

**结论：LatentSync 属于业务线 1，与本线无关。**

## 二、本线当前状态与新增诉求

**现状**：FaceFusion（inswapper_128 + region 遮罩 v2 参数）已完成换脸，效果可接受。

**新增诉求**：
1. **形象要使用图片人物的形象**——工作人员的脸型无论胖瘦，都不能体现在成片里
2. **发型也要从照片带过来**——FaceFusion 只换内脸，头发还是工作人员的

隐性约束（来自客户历史反馈与实验）：
- 不能有明显嘴部贴图、耳朵消失等穿帮
- 除人物头部外，其余部分（背景、身体、动作、语音）保持原视频

## 三、问题的技术本质：这不是"换脸"，是"换头"

FaceFusion 换不了头发的根源：inswapper 是 128×128 的模型，**只生成"内脸椭圆区"的像素，画面里根本没有头发像素可贴**。遮罩只决定"往哪贴"，模型生成不了头发。

所以真实需求等价于：

> **把视频中工作人员的整颗头（脸+轮廓+发型）替换为照片人物的头；头部动作/表情/口型跟随原视频；脖子以下与背景不动。**

**产品边界必须先定**：身份证照片只有头和肩，**没有身体信息**——"体型替换"无数据来源。因此拍摄规范应定为**胸像/半身构图**，让换头覆盖人物全部特征，需求即闭环。全身视频=人体再演，是另一个量级的难题，不碰。

## 四、对"DreamID-V 先生成肖像再替换"方案的判定

该方案**分两步走的思路是对的**，但有两个问题：

1. **DreamID-V 不是肖像生成模型**：它是视频换脸模型（视频进、视频出）。生成单张标准肖像应该用图像域模型（InstantID / PuLID / Qwen-Image-Edit / FLUX.1 Kontext 等）。
2. **静态肖像无法直接"替换"进视频**：贴上去头不会动、不会说话。中间必须有一个**再演（reenactment）模型**把视频里的动作传给照片。补上这一环，方案即成立。

## 五、可行方案

### 方案 A（主推）：肖像生成 → 再演驱动 → 回贴合成

```
身份证照片 ──①肖像归一化──▶ 标准肖像（完整发型/露耳/高分辨率/光照均匀）
                                │
工作人员视频 ──────────────②再演──▶ 肖像被驱动：点头/表情/口型跟随视频
                                │
工作人员视频 ──③回贴合成──────────▶ 换头成片
              （抠掉原头→补背景→贴新头→色彩匹配）
```

**①肖像归一化**（每客户一次，分钟级）：用图像编辑/身份保持模型把身份证照"洗"成标准肖像——补全发型、去高光油光（DreamID-V 实验已踩过此坑）、提分辨率到 1024+、光照向视频基调靠拢。候选：Qwen-Image-Edit / FLUX.1 Kontext（指令式编辑）、InstantID / PuLID + ControlNet（身份保持，可用视频截帧姿态控制生成角度匹配的头像）。

**②再演**（每条视频，4090 上秒级~分钟级）：**LivePortrait**（开源，快手）。源=肖像，驱动=工作人员视频，relative 模式 + stitching。对整张头做变形驱动，**发型/脸型/耳朵全部来自照片，口型表情来自视频**。宣读类视频头部动作小，正好在它最稳的区间。

**③回贴合成**（每帧，快）：分割原视频人头（含头发）→ 背景底板补洞 → 新头按关键点对齐贴回 → 脖子处羽化 + 肤色传递。

**主要风险与对策**：

| 风险 | 对策 |
|---|---|
| 身份证照分辨率低（358×441 常见），头发纹理糊 | ①中做放大增强 |
| 脖子接缝、肤色差 | 边界压在衣领/下颌处羽化；色彩传递 |
| 手/证件遮挡脸部 | 拍摄规范规避（正面无遮挡） |
| 大幅转头时再演身份漂移 | 拍摄规范限定小幅动作；宣读场景天然满足 |

详细实验计划见：[换头方案A实验计划.md](换头方案ALivePortrait实验计划.md)

### 方案 B（备选，低推荐）：DreamID-V 裁剪域重生成

只裁人头周围区域送 DreamID-V（生成式换头，形象保真确实好——客户喜欢的就是它的形象），分段交叉淡化 + 回贴。**不作主线**：3 秒分段跳变是架构性的（已实测）；单条 25 分钟；跨段形象漂移。仅在方案 A 合成质量过不了关时回头看。

### 方案 C（现状增强，对照基线）：FaceFusion + hyperswap_256 + occlusion + gfpgan

换 hyperswap_256（服务器上已有权重）后脸型轮廓会比 inswapper_128 好一点，但**头发仍做不了**。保留作对照基线。

## 六、明确排除的路线

| 路线 | 排除原因 |
|---|---|
| FaceFusion 遮罩扩到头发 | 模型不生成头发像素，物理上不可能 |
| 静态肖像逐帧贴到视频 | 头不会动；逐帧变形即等于方案 A 的再演 |
| 可灵 / OmniHuman / 即梦等商业 API | **身份证素材上传第三方 = 合规红线**（引擎复查 2026-08-21 已明确） |
| InfiniteTalk 类整帧 V2V | 5.4 小时/14 秒，已出局 |
| LatentSync / MuseTalk | 属于业务线 1（口型重写），本线语音本来就对口 |

## 七、验证顺序（先证明再工程化）

1. **半天**：服务器搭 LivePortrait，拿 11.png + wlh.mp4 手工跑通"肖像→再演"，看发型/脸型/口型保真度——**整条路线成立与否的关键闸门**
2. **半天**：用图像编辑模型从 11.png 生成标准肖像，替换后再跑①②，对比肖像质量
3. **一天**：写回贴合成脚本（分割+底板+羽化+色彩传递），出第一条完整样片
4. 三方并排（FaceFusion v2 / DreamID-V / 方案 A）送审，通过后工程化

## 八、拍摄规范建议（产品交付物，随方案 A 一并输出）

工作人员录制视频时遵守：

1. **胸像/半身构图**，正面或微侧（<15°），头部动作幅度小（宣读自然幅度即可）
2. **静态背景 + 固定机位**（背景底板补洞的前提，动态背景成本翻倍）
3. 脸部无遮挡（手/证件不要挡脸）
4. 光照均匀，避免强侧光（减少肤色传递压力）
5. 发型蓬松度、头发长度尽量"中性"（与客户群体常见发型的差异越小，合成越自然）
